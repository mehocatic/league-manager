# My 10x Solution - Meho Ćatić

**League Manager**: a backend that turns entering football results into a finished table, written match reports and a weekly PDF.
Repository: <https://github.com/mehocatic/league-manager>

## The problem

Lower football leagues in Bosnia and Herzegovina, such as **2. liga FBiH Zapad** (14 clubs, 7 matches per round), are often followed through social media pages run by fans. A friend of mine who follows regional football publishes the results, the table and the top scorers on Facebook after every round. He does it all by hand, and it takes him **1 to 2 hours or more per round**:

- recalculating the standings table (points, wins, draws, losses, goals, goal difference, tie-breakers),
- updating the top scorers list,
- putting it together and posting it.

Most of that time goes into work a computer can do, and a single mistake in one score makes the whole table wrong.

## The 10x idea

The person running the page does only the part a computer cannot do: **enter each result and its scorers**. Everything else is generated:

| By hand today                    | With League Manager                                                                 |
| -------------------------------- | ----------------------------------------------------------------------------------- |
| Recalculate the table            | Calculated from the results on every request, cached until the next change          |
| Update the top scorers           | Calculated from the entered scorers                                                 |
| No match reports today           | A Bosnian report per match, generated by Gemini from the facts and validated        |
| Build and post the round summary | A PDF with results, reports, table and top scorers, generated every Monday at 08:00 |

From 1 to 2 hours or more per round down to entering 7 results. In testing, generating all 7 match reports for a round took 26 seconds.

The calculated table was checked against the **official federation table after round 9**: all 14 rows and every column match, and an automated test keeps it that way.

## How it works

1. The admin logs in (JWT) and enters a result with its scorers. The API checks it: the number of scorers must match the score, every scorer must play for one of the two teams, minutes must be valid.
2. Saving the result clears the cached table and top scorers, so the next public request recalculates them once.
3. On request (or automatically for the weekly report), Gemini writes a short Bosnian match report. It only receives facts from the database, and its answer is stored only if it states both clubs, the exact score, every scorer and every goal minute in the right order.
4. Every Monday at 08:00 (Sarajevo time) a background job takes the latest played round, fills in missing match reports and stores a PDF: results with dates, scorers and reports, the table after that round and the top scorers. If the AI is unavailable, the PDF is produced anyway, just without the missing reports.
5. Everyone else (fans, clubs) reads the table, fixtures, match details and PDFs without logging in.

Real data is used where it is public (club names, fixtures, results of rounds 1 to 9). Players and scorers are fictional.

## The concepts (all 7)

| Concept             | How it is used                                                                                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **API endpoints**   | REST API with ASP.NET Core controllers; each endpoint calls one use case through own CQRS interfaces (no MediatR). Errors are returned as ProblemDetails with correct status codes (400, 401, 403, 404, 409, 429, 503).              |
| **Database**        | SQLite with EF Core: migrations applied on startup, all rules (unique names, check constraints, delete behaviour) in configuration classes, seed data from CSV.                                                                      |
| **Authentication**  | JWT bearer tokens with an admin role; passwords hashed with PBKDF2; login limited to 5 attempts per minute per IP; no password or signing key in Git.                                                                                |
| **Background job**  | A `BackgroundService` that runs every Monday at 08:00 Europe/Sarajevo time, including the summer/winter time switch.                                                                                                                 |
| **PDF reporting**   | QuestPDF renders the weekly round report; reports are stored per round and downloadable by everyone.                                                                                                                                 |
| **Caching**         | `IMemoryCache` for the table and top scorers, invalidated when a result is entered or a team is added.                                                                                                                               |
| **LLM integration** | Gemini writes match reports. Input is structured facts only; output is validated (facts, goal order, Bosnian case endings) with one retry; rate limits are respected; every call is logged with tokens, duration and estimated cost. |

No concept was swapped.

## Run it

```bash
git clone https://github.com/mehocatic/league-manager.git
cd league-manager
dotnet run --project src/LeagueManager.Api
```

Requires the .NET 11 SDK (RC 2). Swagger UI opens at <http://localhost:5250/swagger>, and the admin password is printed once in the console. AI reports are optional and need a free Gemini key:

```bash
dotnet user-secrets set "Gemini:ApiKey" "<your-key>" --project src/LeagueManager.Api
```

The README contains a 5-minute demo path, the configuration options and a table that maps each concept to the files where it lives. `dotnet test` runs 53 tests without network access.

## What I learned

- **LLM output needs the same validation as user input.** An early report said the final score was set by the 70th-minute goal, when the last goal came in the 88th. Sending the running score with each goal and checking the order of goal minutes fixed this in code, not just in the prompt.
- **Real language is hard to validate.** Bosnian declines names ("FK Vitez" becomes "FK Viteza"), so exact text matching failed. A small list of case endings solved it without accepting typos.
- **Free tiers have real limits.** Model availability changed during the project and the free tier allows only a few requests per minute, so the client reads Google's error messages, waits when asked and logs every call.
